# Per-model capability delta (drive-epic)

Read once per session for your own seat, and when routing to a seat. Same playbook; each seat
adjusts on the axes the fleet has measured. §2c (no idle lanes) is not a per-model delta: it binds
every driver seat. Model ids, pins, review seats and sign-off seats are live data in `/api/rules`
(rules core P2) and `lu_machinery/config/model_catalog.yaml`; the rows below are behaviour, not the
roster, and never restate it.

Cursor runs Grok reviews inside the read-only dispatch boundary; a brief may request shell
commands, interpreter probes, scripts and named tests under the
[review-loop capability rules](../../review-loop/references/brief.md#commands-a-read-only-reviewer-can-run).

| Seat | Delta |
| --- | --- |
| **Grok (native CLI)** | Tool-backed claims bind here as on every seat: never assert a word, stress, gate, count or SHA without the raw tool output quoted. Its 500K window means leaning on plane and metrics queries, not holding fleet state. Grok has no SessionStart hook, so on a cold start read the pinned facts in `.claude/<lane>-epic/DRIVER-STATE.md`, then run `lu-driver-state render --lane <lane>` and `lu-driver-state check --lane <lane>`. Grok holds no Ukrainian authoring, review or judging seat (rules core P2). **No solo (operator 2026-07-27):** in the driver seat you dispatch, settle, review and merge; you do not do multi-file implementation, quick-fix heroics or dictionary rabbit holes yourself. No-solo means you do not implement, not that you stop thinking. |
| **Sonnet 5.5** | The practical seat for well-scoped work, bug fixes and polished English reports, runbooks, PR and issue prose. Keep Ukrainian curriculum content with the sanctioned language lanes. Security code (hooks, launchers, credentials, admission, sandbox) is never written or reviewed on Sonnet; its seats and its `--risk critical` review follow rules core P2 and the resolver. Escalate hard, open-ended judgment to Opus 5.5 or Sol 6.2. Above the review policy's Low tier, a review you route goes outside the author's family (an Anthropic family, here). |
| **Gemini / AGY** | Ukrainian work and well-defined implementation from a complete one-unit brief with acceptance criteria. Do not self-decompose into serial micro-PRs; the accountable orchestrator owns sequencing. |
| **Claude (driving a track)** | Opus 5.5 for hard coding and deep review (security-code seats follow rules core P2 and the resolver); Sonnet 5.5 for well-scoped everyday work and English deliverables; Ukrainian content stays with the sanctioned language lanes. Opus 5.5 cannot disable thinking; control cost with `effort` (`fleet-shared-doctrine.md` § Opus 5.5 `/effort` decision topology). |
| **Codex / GPT-6** | Sol handles coding and review; Luna handles routine bounded work and scouting; what admits a Luna dispatch (a bounded brief, or a Sol advisory envelope) is rules core P2. The launcher injects the cold-start board and binds at most one fresh CLI rollover; stop on any SessionStart setup error. Codex has no Monitor-equivalent watcher: use bounded foreground waits. |
| **Sol driver (Codex)** | These rules apply to fresh, resumed and post-compaction starts. Write plain, readable sentences in every message, including status reports and handoffs; never use run-together tokens or arrow chains, and spell identifiers out. For ordered work with current hydration, the launcher-held lease and tracker assignment are authority enough; never request extra successor proof, and stop if authority or hydration is missing, the operator pauses work or scope conflicts with policy. Read only what the next action needs and do not re-read rules or skills the launcher already injected. Keep `DRIVER-STATE.md` under 4 KB; use bounded excerpts on an oversized one and record lane work in the tracker. Limit shell and web output to the lines you need, and treat incomplete evidence as unverified. |
| **Cursor** | `launcher_core.sh` refuses Auto, Fast, an empty model and a forwarded `--model`; the driver seat never runs Auto. This driver session is the Cursor lane: never dispatch to the Cursor agent from inside it (deadlock and quota contention); the lease serializes one driver per epic stream and the dispatcher does not fail closed against a live Cursor driver lease, so capacity is only a hint. A driver of record needs an attested `resolved_model`. **Anti-passive:** never leave an owned PR sitting. A turn that does not merge or clean a CLEAN gate must dispose the next issue or name a §2c code, and a CLEAN, MERGEABLE PR whose Merge policy gates hold (the review its tier requires, recorded at the exact head and not rejected, and a green same-head CI Gate) is enqueued the same turn through the publisher's merge command (no `--delete-branch`). Ending on "review or CI pending", or reporting a worker's status from memory, is a driver defect. |
